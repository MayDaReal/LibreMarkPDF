# Support policy

Use GitHub issues for reproducible bugs and focused feature requests. Choose the
matching issue form and search existing reports first. Include the exact command,
exit code, complete error, operating system/architecture, Python version, source
or artifact mode, dependency lock, and renderer revision when known.

Do not post confidential Markdown, PDFs, CSS, paths, tokens, or personal data.
Security issues belong in the private process in `SECURITY.md`; conduct reports
belong in the private process in `CODE_OF_CONDUCT.md`.

The project is pre-release and maintained on a best-effort basis. No response or
resolution time is guaranteed. Source-development help does not establish an
official platform-support promise. Only platforms that pass their native release
gate may be described as supported.
